# character_viewer

マイク音声に超低遅延で反応して、透過背景のイラストを切り替える OBS 用キャラクター表示ツール（PNGTuber 型）。

## 目標

- 発話を検出してから絵が切り替わるまで **約 10〜40ms**
- 透過背景のまま OBS の配信・録画画面に重ねられる
- 作るのも使い続けるのも **完全無料**（OSS のみ、サーバー不要、すべてローカルで動作）
- 単純な画像切り替えから始め、段階的に機能を追加していく

## 構成（予定）

```
[コンデンサーマイク] → [オーディオIF] → PC
        │
        ▼
┌───────────────────────────┐      WebSocket (localhost)     ┌──────────────────────────┐
│ 音声エンジン (Rust)        │ ─────────────────────────────▶ │ 描画 (OBS ブラウザソース) │
│  WASAPI 共有モード・小バッファ │   状態イベント (数十バイト)      │  TypeScript + PixiJS     │
│  音量判定 + ヒステリシス     │                                 │  透過 PNG を切り替え表示  │
│  VAD (誤検出の抑制)          │                                 └──────────────────────────┘
│  状態遷移                   │
└───────────────────────────┘
```

| 層 | 技術 |
|---|---|
| アプリ本体 | Rust + Tauri 2 |
| 音声入力 | `cpal` / `wasapi` |
| 発話判定 | 自前 DSP（RMS + ヒステリシス + 保持時間）、補助に WebRTC VAD / Silero VAD |
| 通信 | `axum` + WebSocket |
| 描画 | TypeScript + Vite + PixiJS v8 |
| OBS 連携 | ブラウザソース、カスタムブラウザドック、obs-websocket v5 |
| イラスト | Krita（レイヤーごとに透過 PNG で書き出し） |

## ロードマップ

- [x] **Step 1**: 音声エンジンの試作。マイクの音量を測り、発話中 / 無音を判定する（実際の声でしきい値を調整済み）
- [x] **Step 2**: 描画側の試作。仮画像で「待機 / 発話 / 放置 / 寝落ち」を切り替える。まばたき
- [x] **Step 3**: OBS に組み込み、録画で声と絵のずれを実測する（中央値 −41ms。気づかれない範囲）
- [ ] **Step 4**: 設定画面（デバイス選択、しきい値、無言の秒数）と画像の即時反映
- [ ] **Step 5**: 口パク・まばたき・揺れなどの動き（パーツ分けした素材を使う）
- [ ] **Step 6**: 拡張（母音リップシンク、叫び差分、シーン連動、ホットキーでの表情切り替え）

## Step 1: 音声エンジンを動かす

必要なもの（すべて無料）: Rust（`rustup`）、Visual Studio Build Tools の「C++ によるデスクトップ開発」

```powershell
cd engine
cargo build --release

# 入力デバイスの一覧
.\target\release\cv-engine.exe --list

# 既定のマイクで判定を開始（Ctrl+C で終了すると遅延の統計が出る）
.\target\release\cv-engine.exe

# キャリブレーション（画面の指示どおりに約 40 秒録音 → しきい値を提案）
.\target\release\cv-engine.exe --calibrate

# 録音済みのキャリブレーションを解析し直す
.\target\release\cv-engine.exe --analyze calibration.wav

# デバイスやしきい値を指定する例
.\target\release\cv-engine.exe --device 2 --channel 1 --on-db -40 --off-db -48 --hold-ms 300
```

| オプション | 既定値 | 意味 |
|---|---|---|
| `--device` | 既定のマイク | 一覧の番号、または名前の一部 |
| `--channel` | 1 | 判定に使う入力チャンネル（1 始まり） |
| `--on-db` | -32 | これを超えたら発話開始（dBFS） |
| `--off-db` | -40 | これを下回る状態が続いたら発話終了 |
| `--hold-ms` | 250 | 発話終了とみなすまでの保持時間 |
| `--hpf-hz` | 80 | 低域ノイズを除くハイパスフィルタ（0 で無効） |
| `--voicing` | 0.75 | 声らしさ（周期性）のしきい値。息・タイプ音を除外する（0 で無効） |
| `--seconds` | なし | 指定秒数で自動終了 |

既定値（-32 / -40 / 0.75）は 2026-11-07 のキャリブレーションで「小声にも反応・雑音で誤反応 0 回・声の捕捉率 99.7%」となった値。
部屋やマイクの設定を変えたら `--calibrate` で測り直す。

メーターの `|` が ON しきい値、`:` が OFF しきい値の位置です。`♪` は「声らしい」と判定された瞬間です。

### 判定の仕組み

1. 80Hz ハイパスで空調・振動などの低域ノイズを除く
2. **声らしさ判定**: 声は声帯の振動で周期的な波形になるが、息やタイプ音は周期性のない雑音。
   NSDF（McLeod Pitch Method の正規化自己相関）で 2.5ms ごとに周期性を調べる
3. 「音量が ON しきい値以上」かつ「声らしい」で発話開始、どちらかが 250ms 途切れたら発話終了

声らしさの確認に 12〜17ms かかるため、検出までの遅延は合計で約 20〜30ms（目標 45ms 以内）。

### 遅延の調査結果（2026-11-07）

- この PC の入力デバイスは、どちらも WASAPI 共有モードの周期が **10ms 固定**（低遅延モード IAudioClient3 非対応）。
  `cargo run --release --example probe_latency` で確認できる
- そのため音声取り込みの待ち時間は平均 約 5ms、最大 約 10ms。判定そのものは 1〜2ms
- ADC・USB 転送などハードウェア側の遅延（数 ms）はソフトからは測れないため、表示値に含まない

## Step 2: 絵を表示する（OBS のブラウザソース）

必要なもの（無料）: Node.js（描画ページのビルドに使う。一度ビルドすれば普段は不要）

```powershell
# 描画ページをビルド（初回と、renderer を変更したときだけ）
cd renderer
npm install
npm run build

# エンジンを起動（描画ページの配信も同時に始まる）
cd ..\engine
.\target\release\cv-engine.exe
```

OBS の設定:

1. ソースに「ブラウザ」を追加
2. URL に `http://127.0.0.1:39540/`、幅・高さはイラストの縦横比に合わせる（仮画像は 1000×1000）
3. 「カスタムフレームレートを使用」にチェックし、OBS の出力と同じ fps にする
4. 「表示されていないときにソースをシャットダウン」「シーンがアクティブになったときにブラウザの表示を更新」はオフ

URL に `?debug` を付けると左上に接続状態・音量・回数（切替・再接続・まばたき・描画）が出て、キー 1〜4 で状態を手動で切り替え、B でまばたきできる。
`?checker` を付けると背景が市松模様になり、普通のブラウザで透過を確認できる（例: `http://127.0.0.1:39540/?debug&checker`）。

| オプション | 既定値 | 意味 |
|---|---|---|
| `--away-secs` | 6 | 無言がこの秒数続いたら「放置」（0 で無効） |
| `--sleep-secs` | 12 | 無言がこの秒数続いたら「寝落ち」（無言の開始から数える。0 で無効） |
| `--port` | 39540 | 描画ページを配信するポート |
| `--renderer-dir` | 自動 | 描画ページのフォルダ（`renderer/dist` を自動で探す） |
| `--avatar-dir` | 自動 | イラスト素材のフォルダ（`avatar` を自動で探す） |

### 絵を差し替える

`avatar/avatar.json` で、状態ごとに表示する画像を指定する（パスは `avatar` フォルダからの相対）。
PNG・SVG・WebP が使える。画像を差し替えたら、OBS のブラウザソースの「現在のページのキャッシュを更新」で反映される。

```json
{
  "states": {
    "idle": {
      "image": "idle.png",
      "blink": { "half": "idle_half.png", "closed": "idle_closed.png" }
    },
    "talk": {
      "image": "talk.png",
      "blink": { "half": "talk_half.png", "closed": "talk_closed.png" }
    },
    "away": "away.png",
    "sleep": "sleep.png"
  }
}
```

- 画像 1 枚だけの状態は `"away": "away.png"` のように文字列で書ける（その状態ではまばたきしない）
- まばたきには「目を閉じた絵」（`closed`）が必要。「半目」（`half`）はあると滑らかになるが省略できる
- まばたき用の絵は、元の絵と **目以外がまったく同じ** にする（Krita なら目のレイヤーだけ差し替えて書き出す）
- `idle` 以外は省略でき、ない状態は近い絵で代用する（発話・放置 → 待機、寝落ち → 放置 → 待機）
- 絵はウィンドウに収まる最大サイズで下端中央に置かれ、縮小しても荒れないようミップマップを使う

### まばたき

機械的に見えないよう、人のまばたきの性質に寄せている（[renderer/src/blink.ts](renderer/src/blink.ts)）。

- 間隔は一定ではなく、右に裾の長い分布（対数正規分布、中央値 3.4 秒、0.7〜9 秒）。1 分あたり約 15〜20 回
- 喋っているときは間隔が短くなる（中央値 2.6 秒）
- 約 12% の確率で 2 回続けて瞬く
- 閉じるのは速く（30〜60ms）、開くのはゆっくり（60〜120ms）。1 回ごとに長さが揺らぐ
- 話し終わり・放置や寝落ちからの復帰で、約 45% の確率で瞬く

`cd renderer; npm test` で、回数・ばらつき・順序のテストが走る。

### ちらつき対策

描画ページは、絵が変わるとき（状態の切り替え・まばたき）だけ描き直し、それ以外は何もしない。
毎フレーム描き直す方式に比べて OBS の負荷が軽く、描き直しのタイミングによるちらつきも起きにくい
（100 秒の試験で描き直しは 30 回。毎フレーム方式なら 6000 回）。
また、エンジンとの接続が一瞬切れても 2 秒間は今の絵を保ち、すぐ戻れば絵は変わらない。

### 遅延の測り方

描画ページは、新しい状態を描いたフレームでエンジンに応答（ack）を返す。エンジンは状態が変わるたびに

```
[  12.345s] ▶ 発話     （直前の無言   3.2s）   検出 14.2 + 表示  9.8 = 合計  24.0 ms
```

のように「音 → 判定」「判定 → 描画フレーム」の内訳を表示し、Ctrl+C で終了すると統計を出す。
ヘッドレスの Edge で測った「判定 → 描画フレーム」は 4〜13ms（ブラウザの描画周期 16.7ms 待ちが大半）。
OBS の合成・出力にかかる時間は含まないので、Step 3 で OBS 込みの実測をする。

### 通信の仕組み

エンジンが 127.0.0.1（この PC の中だけ）で HTTP と WebSocket を待ち受ける。

- 音声スレッドが発話の開始・終了を検出したら、制御スレッドをその場で起こす（ロックなし）
- 制御スレッドが状態を決め、接続中のすべての描画ページへ即座に送る（Nagle 無効で溜めずに送信）
- メッセージの形式は [engine/src/server.rs](engine/src/server.rs) の先頭に記載

renderer を改造するときは、エンジンを起動したまま `npm run dev` で開発サーバー（http://localhost:5173/）を使うと、保存するたびに即反映される。

## Step 3: 声と絵のずれを録画で測る

視聴者が見るのは OBS の録画・配信映像なので、そこで「声が始まってから絵が切り替わるまで」を実測する。
エンジンが表示する遅延には OBS の映像合成・音声処理の時間が入らないため、こちらが本当の値になる。
視聴者にとって大事なのは「声と絵が揃っているか」なので、ずれの向きに応じて OBS 側で揃えられる。

必要なもの（無料）: ffmpeg（`winget install Gyan.FFmpeg`）

1. エンジンを起動したままにする
2. OBS に「ブラウザ」ソースを追加し、URL を `http://127.0.0.1:39540/?sync`、幅・高さを 200×200 にする。
   発話中は白、それ以外は黒の四角になる。画面の端など、録画に映る場所に置く
3. ゲーム音などは止め、録画を開始する
4. 「あっ」「たっ」と短く区切って、1 秒以上あけながら 15〜20 回声を出す（普段の声の大きさで）
5. 録画を止め、エンジンとは別の PowerShell で解析する

```powershell
cd C:\character_viewer\engine
.\target\release\cv-engine.exe --measure-av "C:\video editing\録画ファイル.mp4"
```

6. 表示された「判定」に従う
   - **絵が遅れている**（正の値）: マイクの「同期オフセット」を増やし、声を絵に合わせて遅らせる
   - **絵が早い**（負の値）: マイクにノイズ除去などのフィルタがあると、録画の音声だけが遅れてこうなる。
     125ms 以内なら視聴者にはほぼ気づかれないのでそのままでよい。ぴったり揃えたいときは、
     描画のブラウザソースに「レンダリング遅延」フィルタを追加して絵を遅らせる（マイクの同期オフセットは増やさない）
7. 測定用のブラウザソースは削除するか非表示にする

判定の目安は ITU-R BT.1359（音が映像より 45ms 以上先だと気づかれやすく、音が後なら 125ms までは気づかれにくい）。

### 測定結果（2026-11-08）

| 項目 | 値 |
|---|---|
| ずれ（中央値） | **−41ms**（絵が声より 41ms 早い） |
| 10〜90% | −55〜+16ms（27 回） |
| 原因（推定） | OBS のマイクのノイズ除去（Alt Denoiser）などで、録画の音声だけが遅れている（絵の遅延 約 40ms と合わせて 約 80ms と推定。未検証） |
| 判断 | 気づかれない範囲なので調整なし。マイクの同期オフセットは 0 のまま |

声がゆっくり大きくなる出だしでは、エンジンのしきい値を超えるまで 100ms 以上かかることがある（+157ms の回）。

| オプション | 既定値 | 意味 |
|---|---|---|
| `--measure-av` | なし | 解析する録画ファイル（mp4 / mkv / hybrid mp4 など ffmpeg が読める形式） |
| `--audio-track` | 1 | マイクが入っている録画の音声トラック |

仕組み: ffmpeg で映像を 64×36 のグレースケールに縮小し、白黒が同じタイミングで切り替わるセルの集まりを四角として見つける。
音声は、切り替えごとにその回の声のピークと直前の雑音を測り、「ピークから 15dB 下、かつ雑音から 10dB 上」を超えた瞬間
（直前 30ms は静か）を声の立ち上がりとする。録画の途中で雑音が変わっても、ノイズ除去・コンプレッサーで音量が変わっていても揃って測れる。
時刻はどちらも録画内のタイムスタンプ（AAC の先頭無音などは除いて揃える）を使う。
ずれが分かっている合成動画（H.264 / AV1、音声のずれあり・なし）で、1 フレーム以内の精度で測れることを確認済み。

## 状態遷移

```
         声を検出（即座に）
 [待機] ─────────────────▶ [発話] ◀── どの状態からも即座に戻る
   ▲                         │
   └── 無音が 0.25 秒続く ────┘
   │
   └─ 無言 6 秒 ▶ [放置] ─ 無言 12 秒 ▶ [寝落ち]   （秒数は --away-secs / --sleep-secs）
```

## イラスト素材のルール

- すべての差分を **同じキャンバスサイズ・同じ位置** で書き出す
- 透過 PNG で、表示サイズの 1.5〜2 倍の解像度にする
- フチや影はイラストには入れず、描画側で付ける
