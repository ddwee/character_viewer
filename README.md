# character_viewer

マイク音声に超低遅延で反応して、透過背景のイラストを切り替える OBS 用キャラクター表示ツール（PNGTuber 型）。
作るのも使い続けるのも **完全無料**（OSS のみ、サーバー不要、すべてこの PC の中で動作）。

## 使い方

### はじめて使うとき

1. 必要なもの（すべて無料）を入れる
   - Rust（https://rustup.rs）と Visual Studio Build Tools の「C++ によるデスクトップ開発」
   - Node.js（https://nodejs.org）
   - Git（https://git-scm.com）
2. このフォルダの **`setup.cmd` をダブルクリック**
   - ビルドとテストをして、デスクトップとスタートメニューに「character_viewer」を作り、アプリを起動する（数分）
3. 設定画面が開いたら、**OBS** のページの手順で OBS にブラウザソースを追加する

### 普段の使い方

- デスクトップの「character_viewer」を起動すると、タスクトレイに常駐して設定画面が開く
- 設定画面のウィンドウを閉じてもアプリは動き続け、OBS への表示も続く（終了はトレイのアイコンを右クリック →「終了」）
- 設定はすべて画面で変えられ、**変えた瞬間に保存・反映**される（保存ボタンはない）
- Windows の起動時に自動で起動させることもできる（メンテナンス →「Windows の起動時に自動で起動」）
- 設定画面は OBS の中でも開ける（OBS のメニュー「ドック」→「カスタムブラウザドック」に `http://127.0.0.1:39540/settings/`）

### 設定画面でできること

| ページ | できること |
|---|---|
| ホーム | いまの状態（話している / 待機 / 放置 / 寝落ち）、OBS と同じ表示のプレビュー、**いまの絵を透過 PNG で保存**（サムネイル作り用）、OBS の接続数、反応の速さの実績、問題の通知 |
| マイク | デバイス・チャンネルの選択、しきい値の位置つきの音量メーター、感度のスライダー、**自動で調整する**（約 40 秒のキャリブレーション） |
| 画像と動き | 状態ごとの絵（通常・半目・閉じ目）をドラッグ＆ドロップで設定、プレビューで各状態を試す、まばたきの有無と頻度、左右反転、放置・寝落ちまでの秒数、素材のフォルダ |
| パーツの調整 | パーツで動かす素材の、回転の中心（●）と揺れものの先端（■）をドラッグで調整、選んだパーツを揺らして確かめる、揺れものの硬さ・収まりやすさ、動きの強さ、「動きを見る」で OBS と同じ動き（喋るまね付き）、**顔の向き・視線・表情を試す**、パーツごとの奥行き、元に戻す |
| カメラ | **カメラで顔の向き・視線・表情を読み取る**（使う / 使わない、カメラの選択、鏡のように動かす）、基準を合わせる、読み取る項目と強さ、今の値の表示、**表情の切り替えとキーの割り当て** |
| OBS | ブラウザソースの追加手順とコピー用 URL、ドックの追加、**声と絵のずれの測定**（最近の録画を選ぶだけ）、ffmpeg のインストール |
| メンテナンス | 部品のバージョン、**更新を確認 / 更新する**、作り直す、前の版に戻す、PowerShell を開く、ログ、フォルダを開く、自動起動、アプリの終了 |

プレビューの「📷 PNG で保存」を押すと、その瞬間の絵を **素材の解像度（縮小なし）の透過 PNG** で「ピクチャ」の `character_viewer` フォルダに保存する（`avatar-日付-時刻-状態.png`）。
左右反転の設定もそのまま反映され、まばたきの途中だったときは目を開けた絵で保存する。「画像と動き」のプレビューなら、状態のボタンで表情を選んでから保存できる。

画像は Krita などで同じファイル名のまま上書き保存しても、自動で読み込み直して OBS の表示にもすぐ反映される。

### 困ったとき

- **設定画面のメンテナンス →「PowerShell を開く」**: 部品の版・今日のエラー・よく使うコマンドを表示した PowerShell が開く
- **アプリが起動しない**: 起動に失敗すると、原因と「もう一度起動する / 作り直す / PowerShell を開く / ログのフォルダを開く」のボタンがある画面が出る。
  それも出ないときは、スタートメニューの「**character_viewer メンテナンス**」から同じ PowerShell を開ける
- **更新のあと調子が悪い**: メンテナンス →「前の版に戻す」（もう一度押すと元に戻る）
- ログ: `%APPDATA%\character_viewer\logs`（`cv-日付.log` が動作の記録、`maintenance-日付.log` が更新の記録）
- 設定: `%APPDATA%\character_viewer\settings.json`（壊れていたら自動で退避して既定値で起動する）

### 更新のしくみ（互換性の問題で動かなくならないように）

メンテナンスの「更新を確認」で、プロジェクト（GitHub）・Rust・部品（Rust と npm）に新しい版があるか調べ、選んだものを更新できる。

- 更新は別のウィンドウ（PowerShell）で進み、経過とエラーがそのまま見える
- **新しい版でビルドとテストが全部通ったときだけ** 入れ替える。アプリは `bin` フォルダのコピーから動いているので、ビルド中もそのまま動く
- 失敗したら、部品の一覧（`Cargo.lock` / `package-lock.json`）とプロジェクトを更新前に戻す。今動いている版はそのまま
- 新しい Rust でビルドできなかったときは、動いていた版に固定する（`rust-toolchain.toml`）。次に Rust を更新するとき、改めて新しい版を試す
- 部品は **互換性を保つ範囲**（semver で大きな変更を含まない版）までしか自動で上げない。大きな変更を含む最新版は一覧に表示だけする
- 入れ替えるとき、直前の版を `bin.prev` に残す（「前の版に戻す」で使う）
- 設定ファイルは、項目が欠けていても知らない項目があっても読める（古い版・新しい版のどちらの設定でも起動できる）
- 描画ページとエンジンの通信は版番号を確かめ、合わなければ画面に表示する

## 構成

```
[コンデンサーマイク] → [オーディオIF] → PC
        │
        ▼
┌─ アプリ cv-app（Tauri 2・タスクトレイ常駐）───────────────┐
│  音声エンジン（Rust）                                      │      WebSocket       ┌──────────────────────────┐
│   WASAPI 共有モード → HPF → 声らしさ判定 → 状態遷移        │ ───────────────────▶ │ 描画ページ                │
│  HTTP / WebSocket サーバー（127.0.0.1:39540）              │   状態・設定・再読込   │  OBS のブラウザソース      │
│  設定 API（/api）                                          │                      │  TypeScript + PixiJS v8   │
│  設定画面のウィンドウ（WebView2）                          │ ◀──── 設定画面 ────── │  （Preact）               │
└────────────────────────────────────────────────────────┘                      └──────────────────────────┘
```

| 層 | 技術 |
|---|---|
| アプリ | Rust + Tauri 2（タスクトレイ、二重起動の防止、WebView2 のウィンドウ） |
| 音声入力 | `cpal`（WASAPI 共有モード） |
| 発話判定 | 自前 DSP（HPF + エンベロープ + NSDF による声らしさ + ヒステリシス + 保持時間） |
| 通信・API | `axum`（HTTP / WebSocket）、`tokio` |
| 描画ページ | TypeScript + Vite + PixiJS v8（1 枚絵は変化時だけ描画、パーツは毎フレーム描画）。ボーン・ばね・口パクは自前の小さな実装 |
| カメラ | MediaPipe Face Landmarker（WebAssembly。アプリの見えないウィンドウで動かし、結果だけをエンジン経由で描画ページへ送る）。モデルは `renderer/public/mediapipe/` に同梱 |
| 設定画面 | TypeScript + Preact（同じ Vite プロジェクト） |
| 更新・保守 | PowerShell スクリプト（`tools/`） |
| イラスト | Krita（透過 PNG で書き出し） |

## イラスト素材のルール

- すべての差分を **同じキャンバスサイズ・同じ位置** で書き出す
- 透過 PNG で、表示サイズの 1.5〜2 倍の解像度にする
- まばたき用の絵（半目・閉じ目）は、元の絵と **目以外がまったく同じ** にする（Krita なら目のレイヤーだけ差し替えて書き出す）
- フチや影はイラストには入れず、描画側で付ける

素材は `avatar` フォルダ（設定画面で変更可）に置かれ、`avatar.json` で状態と画像を対応づける。設定画面で画像を選ぶと自動で書き換わる。

```json
{
  "states": {
    "idle": { "image": "idle.png", "blink": { "half": "idle_half.png", "closed": "idle_closed.png" } },
    "talk": { "image": "talk.png", "blink": { "half": "talk_half.png", "closed": "talk_closed.png" } },
    "away": "away.png",
    "sleep": "sleep.png"
  }
}
```

`idle` 以外は省略でき、ない状態は近い絵で代用する（発話・放置 → 待機、寝落ち → 放置 → 待機）。

### パーツを重ねてボーンで動かす

`avatar.json` に `rig` を書くと、状態ごとの絵の代わりにパーツを重ねて動かす（`states` は使わない）。

- パーツはすべて **同じキャンバスサイズで位置合わせ済み**（重ねるだけで元の絵になる）にする
- 動いたときに隙間が見えないよう、**隠れる部分も描いておく**（前髪の下のおでこ、頭の下の首、後ろ髪の頭に隠れる部分）
- 目・口は差分の線画だけ（肌は顔のパーツに描く）。眉は顔に描き込まない
- パーツをフォルダ（`parts/` など）に分けてもよい。1 段下のフォルダまで、上書き保存を検出して読み込み直す

```json
{
  "rig": {
    "size": [1024, 1024],
    "bones": {
      "body":      { "pivot": [515, 1023] },
      "neck":      { "parent": "body", "pivot": [518, 730] },
      "head":      { "parent": "neck", "pivot": [518, 640] },
      "brows":     { "parent": "head", "pivot": [511, 398] },
      "backHair":  { "parent": "head", "pivot": [540, 250], "spring": { "length": 400, "frequency": 2.6 } },
      "frontHair": { "parent": "head", "pivot": [518, 220], "spring": { "length": 320, "frequency": 3.4 } }
    },
    "layers": [
      { "bone": "backHair", "image": "parts/01_back_hair.png", "bend": {} },
      { "bone": "neck", "image": "parts/02_neck.png" },
      { "bone": "body", "image": "parts/03_body.png", "bend": { "end": 300, "curve": 1 } },
      { "bone": "head", "image": "parts/04_face.png" },
      { "bone": "head", "mouth": { "closed": "parts/05_mouth_closed.png", "half": "parts/05_mouth_half.png", "open": "parts/05_mouth_open.png" } },
      { "bone": "head", "eyes": {
          "open": "parts/06_eyes_open.png", "half": "parts/06_eyes_half.png", "closed": "parts/06_eyes_closed.png",
          "blink": { "half": "parts/06_eyes_half_blink.png", "closed": "parts/06_eyes_closed_blink.png" } } },
      { "bone": "brows", "image": "parts/07_eyebrows.png" },
      { "bone": "frontHair", "image": "parts/08_front_hair.png", "bend": {} }
    ]
  }
}
```

| 項目 | 意味 |
|---|---|
| `bones` | ボーン。`pivot` は回転の中心（画像の px）、`parent` は親（親が動くと一緒に動く） |
| `layers` | パーツ。**下から順に重ねる**（親子とは無関係。後ろ髪は頭に付くが首より下に描ける） |
| `eyes` | 目。`half`・`closed` は表情の絵（寝落ちなど `states` の `eyes` で固定するとき）。`blink` に瞬き専用のコマ（まぶたが下りてくる絵）を書くと瞬きはそちらを使う。`blink` がなければ `half`・`closed` で瞬きする |
| `bend` | しなる（メッシュ変形）。絵を格子状の網に分け、根元（回転の中心の近く）は動かさず、離れるほどボーンの動きどおりにする。髪は毛先だけが揺れ、体は裾が動かず胸から上だけが伸び縮みする。`start` 動かない範囲 px、`end` 全部動く距離 px（省略すると揺れものの長さ、なければ絵の高さの 40%）、`curve` 曲がり方、`axis` 向き（省略すると揺れものの向き、なければ中心から絵の中央へ）、`grid` 網の目の数（既定 16×16）。`true` か `{}` で既定値 |
| `spring` | 揺れもの。`length` 先端までの長さ、`frequency` 揺れの速さ（回/秒）、`damping` 収まりやすさ（0〜1）、`maxAngle` 最大の傾き（度）、`stretch` 伸び縮み |
| `motion` | 動きの強さ（省略可）。`breath`（`period` 秒・`amount` 伸び率）、`sway`（待機中の `angle` 度・`shift` px・`period` 秒）、`talk`（喋るときの `bounce` px・`angle` 度・`shift` px・`stretch` 体の伸び縮み）、`brows.lift` px、`neckShare` |
| `states` | 状態ごとの姿勢（省略可）。`eyes`（`open`/`half`/`closed` で固定、`null` でまばたき）、`headAngle` 度、`headDrop` px、`breathSlow`・`breathDeep` 倍率、`sway` 倍率。既定では寝落ちで目を閉じてうつむく |

動きを付けるボーンの名前は決まっている: `body`（呼吸）、`neck`・`head`（頭の揺れ）、`brows`（喋ると上がる）。

#### 顔の向き・視線・表情（カメラ対応の素材）

パーツを細かく分けると、顔の向き・視線・表情を付けられる（カメラを使わなくても、待機中に顔の向きが少しゆらぐ）。

```json
"bones": { "frontHair": { "parent": "head", "pivot": [1010, 330], "depth": 1.3, "spring": { "length": 380 } } },
"layers": [
  { "bone": "head", "image": "parts/06_ear_l.png", "depth": -0.3 },
  { "bone": "head", "image": "parts/07_face.png" },
  { "bone": "head", "slot": "cheek", "depth": 0.6, "frames": { "blush": "parts/08_blush.png", "pale": "parts/08_pale.png" } },
  { "bone": "head", "image": "parts/09_nose.png", "depth": 1.4 },
  { "bone": "head", "slot": "mouth", "depth": 1, "frames": { "closed": "…", "half": "…", "open": "…", "i": "…", "u": "…", "smile": "…", "smile_open": "…", "frown": "…" } },
  { "bone": "head", "slot": "eyeL", "id": "whiteL", "depth": 1, "frames": { "open": "…white_l.png", "half": "…white_half_l.png", "wide": "…white_wide_l.png" } },
  { "bone": "head", "image": "parts/12_pupil_l.png", "clip": "whiteL", "gaze": [18, 10], "depth": 1 },
  { "bone": "head", "slot": "eyeL", "depth": 1, "frames": { "open": "…", "wide": "…", "half": "…", "closed": "…", "smile": "…", "squeeze": "…" } },
  { "bone": "brows", "slot": "browL", "frames": { "normal": "…", "up": "…", "worried": "…", "angry": "…" } }
],
"expressions": {
  "smile": { "eyes": "smile", "mouth": "smile" },
  "shy": { "cheek": "blush", "mouth": "smile" }
}
```

| 項目 | 意味 |
|---|---|
| `depth` | 奥行き。顔の向きに合わせて、手前のパーツ（正。前髪・鼻・目）は向いた方へ、奥のパーツ（負。後ろ髪・耳）は逆へずれて、立体的に見える。1 で `motion.turn` の量（既定 横 40px・縦 24px）だけずれる。ボーンに書くと、そのボーンのパーツの既定値になり、揺れものが振り向きに遅れてついてくる |
| `slot` + `frames` | 差し替えパーツ。スロット（`mouth`・`eyeL`・`eyeR`・`browL`・`browR`、ほか `cheek`・`tears` など自由な名前）ごとに「値 → 画像」を書く。今の値の絵を持たないパーツは隠れる（閉じ目のときの白目と瞳）。左右は**絵の左右**（`eyeL` = 絵の左側の目）。`mouth`・`eyes` はこの短い書き方（`eyes` は両目で 1 枚のスロット） |
| 目の値 | `open`・`wide`（見開き）・`half`・`down`（伏し目）・`closed`・`smile`（笑った目）・`squeeze`（ぎゅっと閉じる）。瞬きは `blink_half`・`blink_closed` があればそれ、なければ `half`・`closed` |
| 口の値 | `closed`・`half`・`open`（音量で切り替え）、`i`・`u`（カメラで読み取った口の形）、`smile`・`frown` などの表情。喋っている間は `表情_open`（`smile_open` など）があればそれを使う |
| 眉の値 | `normal`・`up`・`worried`・`angry` |
| `id` / `clip` | 切り抜き。`clip` に書いた `id` のパーツの形（不透明な部分）の中だけに描く。瞳を白目の中だけに表示するのに使う |
| `gaze` | 視線で動く量（px。左右, 上下）。瞳に付ける |
| `expressions` | 表情（スロットの値の組み合わせ）。`eyes`・`brows` は左右の両方に効く。設定画面の「カメラ」やキーで切り替える |
| `motion.turn` | `x`・`y` 顔の向きでずれる量（px）、`sway` 待機中に向きをゆらす量、`talk` 喋るときにゆらす量 |

素材にない値は近い絵で代用する（「い」の口がなければ半開き、見開いた目がなければふつうの目、など）。
パーツは透明な余白を切り詰めて GPU に送るので、2048×2048 のキャンバスでパーツが 60 枚あっても、メモリは絵のある範囲の分しか使わない。

確認用に、描画ページの URL に `?face=yaw:0.5,pitch:-0.2,roll:5,gx:1,eyeL:closed,expr:smile` のように書くと、顔の向き・視線・スロットの値・表情を固定できる。

### カメラで顔を読み取る

設定画面の「カメラ」で「カメラを使う」を入れると、顔の向き・視線・まばたき・眉・口の表情を読み取ってキャラクターに反映する（パーツで動かす素材のとき）。

- 読み取りは MediaPipe Face Landmarker で、**この PC の中だけ**で行う（映像はどこにも送らない。無料）
- 口パクは今までどおり声で動かす（カメラは 30 回/秒なので、声のほうが速い）。カメラは、声が出ていないときの口の開き・口の形（い・う）・笑顔などに使う
- カメラに顔が映っている間は、黙っていても「放置」「寝落ち」の姿勢にならない。顔が見つからなくなったら、自動の動きに戻る
- 初めて使うときは、カメラの使用を許可する確認が「カメラの映像」のウィンドウに出る。このウィンドウは閉じても読み取りは続く
- カメラの位置や顔つきは人によって違うので、最初に「基準を合わせる」（正面を向いた、ふつうの顔で押す）を行う
- 赤面・涙のようにカメラで読み取れない表情は、「表情を切り替える」のボタンか、割り当てたキーで出す（キーは、OBS やゲームを使っている間も効く。同じキーでもう一度押すと解除）
- OBS で同じカメラの映像も使う場合、カメラによっては 2 つのアプリから同時に開けない。そのときは OBS 側でカメラを使わないか、仮想カメラなどで分ける

ブラウザだけで使う（アプリを使わない）ときは、`http://127.0.0.1:39540/tracker/` を開いたままにする。

回転の中心・揺れもの・しなり・動きの強さは、設定画面の「パーツの調整」でドラッグやスライダーで変えられる（avatar.json の rig が書き換わる）。
avatar.json だけが変わったときは、描画ページは画像を読み直さずに組み直すので、調整がすぐ OBS の表示に反映される。

口は、喋り始めはエンジンの「発話」の通知（最速）で即座に開き、喋っている間は音量（約 100 回/秒）で
閉じ / 半開き / 開き を切り替える。音量は最近のピークを基準にした相対値で見るので、声の大きさやマイクの距離が変わっても動く。

## 技術メモ

### 状態遷移

```
         声を検出（即座に）
 [待機] ─────────────────▶ [発話] ◀── どの状態からも即座に戻る
   ▲                         │
   └── 無音が 0.25 秒続く ────┘
   │
   └─ 無言 6 秒 ▶ [放置] ─ 無言 12 秒 ▶ [寝落ち]   （秒数は設定画面で変更）
```

### 判定の仕組み

1. 80Hz ハイパスで空調・振動などの低域ノイズを除く
2. **声らしさ判定**: 声は声帯の振動で周期的な波形になるが、息やタイプ音は周期性のない雑音。
   NSDF（McLeod Pitch Method の正規化自己相関）で 2.5ms ごとに周期性を調べる
3. 「音量が話し始めのしきい値以上」かつ「声らしい」で発話開始、どちらかが 250ms 途切れたら発話終了

声らしさの確認に 12〜17ms かかるため、検出までの遅延は合計で約 20〜30ms（目標 45ms 以内）。
既定値（話し始め -32dB / 話し終わり -40dB / 声らしさ 0.75）は 2026-11-07 のキャリブレーションで
「小声にも反応・雑音で誤反応 0 回・声の捕捉率 99.7%」となった値。部屋やマイクを変えたら「自動で調整する」で測り直す。

キャリブレーションは、無音・呼吸・タイプ音・小声・普段の声を録音し、「声らしさ × 音量しきい値」の候補 70 通りを
実際に判定へ通して（並列）、雑音での誤反応が少なく声をよく捉える設定を選ぶ。

### 遅延の調査結果

- この PC の入力デバイスは、どちらも WASAPI 共有モードの周期が **10ms 固定**（低遅延モード IAudioClient3 非対応）。
  `cargo run --release -p cv-engine --example probe_latency` で確認できる
- そのため音声取り込みの待ち時間は平均 約 5ms、最大 約 10ms。判定そのものは 1〜2ms
- 判定 → 描画フレームは 4〜14ms（ブラウザの描画周期待ちが大半）。描画ページが描いたフレームでエンジンへ応答（ack）を返して測る
- 音声スレッドが発話の開始・終了を検出したら、制御スレッドをその場で起こす（ロックなし）。描画ページへは Nagle 無効で即送信
- ADC・USB 転送などハードウェア側の遅延（数 ms）はソフトからは測れないため、表示値に含まない

### 声と絵のずれ（録画で実測、2026-11-08）

視聴者が見るのは OBS の録画・配信映像なので、そこで「声が始まってから絵が切り替わるまで」を測る（設定画面の OBS ページ）。

| 項目 | 値 |
|---|---|
| ずれ（中央値） | **−41ms**（絵が声より 41ms 早い） |
| 10〜90% | −55〜+16ms（27 回） |
| 原因（推定） | OBS のマイクのノイズ除去（Alt Denoiser）などで、録画の音声だけが遅れている（未検証） |
| 判断 | 音が映像より後の向きは 125ms まで気づかれにくい（ITU-R BT.1359）ので調整なし。マイクの同期オフセットは 0 のまま |

仕組み: 描画ページを `?sync` で開くと発話中は白・それ以外は黒の四角になる。ffmpeg で録画を 64×36 のグレースケールに縮小し、
白黒が同じタイミングで切り替わるセルの集まりを四角として見つける。音声は切り替えごとに、その回の声のピークと直前の雑音から
「ピークから 15dB 下、かつ雑音から 10dB 上」を超えた瞬間を声の立ち上がりとする。時刻は録画内のタイムスタンプ
（AAC の先頭無音などは除いて揃える）を使う。ずれが分かっている合成動画（H.264 / AV1）で、1 フレーム以内の精度を確認済み。

### まばたき

機械的に見えないよう、人のまばたきの性質に寄せている（[renderer/src/blink.ts](renderer/src/blink.ts)）。

- 間隔は一定ではなく、右に裾の長い分布（対数正規分布、中央値 3.4 秒、0.7〜9 秒）。1 分あたり約 15〜20 回
- 喋っているときは間隔が短くなる（中央値 2.6 秒）。頻度は設定画面で 0.5〜2 倍に変えられる
- 約 12% の確率で 2 回続けて瞬く
- 閉じるのは速く（30〜60ms）、開くのはゆっくり（60〜120ms）。1 回ごとに長さが揺らぐ
- 話し終わり・放置や寝落ちからの復帰で、約 45% の確率で瞬く

### ちらつき対策

描画ページは、絵が変わるとき（状態の切り替え・まばたき）だけ描き直し、それ以外は何もしない。
毎フレーム描き直す方式に比べて OBS の負荷が軽く、描き直しのタイミングによるちらつきも起きにくい
（100 秒の試験で描き直しは 30 回。毎フレーム方式なら 6000 回）。
パーツをボーンで動かす素材だけは、常に動いているので毎フレーム描く（パーツ 8〜12 枚程度なので負荷は小さい）。
エンジンとの接続が一瞬切れても 2 秒間は今の絵を保つ。素材の読み込み直しは、新しい絵がすべて揃ってから入れ替える。

### 安全のため

- サーバーは 127.0.0.1 だけで待ち受ける（同じ PC 以外からは接続できない）
- 設定 API は Host・Origin ヘッダーを確かめ、変更系の操作には専用ヘッダーを必須にする（ブラウザで開いた別のサイトからは操作できない）
- 画像の保存は決まった名前・決まった拡張子だけ（パスの書き換えはできない）

## 開発者向け

```
character_viewer/
  setup.cmd        初回セットアップ（tools/install.ps1）
  engine/          音声エンジン（ライブラリ + コマンド版 cv-engine）
  app/             アプリ（Tauri 2。エンジンを組み込み、設定画面のウィンドウとトレイ）
  renderer/        描画ページ（index.html）と設定画面（settings/）
  avatar/          イラスト素材（仮画像）
  tools/           更新・作り直し・元に戻す・PowerShell 用のスクリプト
  bin/             インストール先（ビルド結果のコピー。git には入れない）
```

```powershell
# まとめてビルド・テストして bin に入れる（アプリは起動し直す）
.\tools\update.ps1

# 個別に
cd renderer; npm run build; npm test          # 描画ページ・設定画面
cargo test --release -p cv-engine             # エンジンのテスト
cargo build --release -p cv-engine -p cv-app  # エンジンとアプリ

# 描画ページ・設定画面を改造するとき（アプリを起動したまま。保存するたびに即反映）
cd renderer; npm run dev    # → http://localhost:5173/ と http://localhost:5173/settings/
```

コマンド版 `cv-engine.exe`（`bin` または `target\release`）は、トラブル時の確認・開発用。普段はアプリを使う。

| 使い方 | 意味 |
|---|---|
| `cv-engine.exe` | アプリと同じくエンジンを動かし、ログをその画面に出す（アプリは終了してから） |
| `cv-engine.exe --list` | 入力デバイスの一覧 |
| `cv-engine.exe --analyze calibration.wav` | キャリブレーション録音を解析し直す（録音は `%APPDATA%\character_viewer\calibration.wav`） |
| `cv-engine.exe --measure-av 録画.mp4 [--audio-track 1]` | 録画から声と絵のずれを測る |
| `--device` `--channel` `--on-db` `--off-db` `--voicing` `--port` | 設定画面の値を一時的に上書き（保存はしない） |

描画ページの URL オプション: `?debug`（状態・音量の表示、キー 1〜4 で状態、B でまばたき）、`?checker`（背景を市松模様に）、`?sync`（遅延測定用）。
WebSocket のメッセージ形式は [engine/src/server.rs](engine/src/server.rs)、設定 API は [engine/src/api.rs](engine/src/api.rs) の先頭に記載。
